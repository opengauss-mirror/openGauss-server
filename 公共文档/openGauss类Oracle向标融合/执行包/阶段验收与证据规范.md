# 阶段验收与证据规范

## 三个阶段

| 阶段 | 任务范围 | 出口 | 本阶段不能冒充已完成的能力 |
|---|---|---|---|
| 基础功能 | E-01/E-02、Q-01-D1、F-01～F-05/F-07、Q/V 的 P1 项 | G-P1：单表三模式、快照/身份/参数/资源、成本/质量，PRE 空域差异已解决 | Join 融合、根据完整 Join 数补搜、POST 精确入口 |
| Join 融合 | J-01～J-07、Q-01-D2、Q/V 的 P2 项 | G-P2：三基准与扩展计划、非唯一/NL、多重集与 OB/O Oracle 对照 | 第三阶段反馈/精确兜底 |
| 质量优化 | F-00、F-09-D、Q-01-D3、F-08/F-09/F-06、Q/V 的 P3 项 | G-P3：三模式补搜、仅 POST 同计划精确入口、完整域、Oracle 重验及质量报告 | 未证明的任意输入跨引擎结果一致或未验收的迁移存储 |

第一、二阶段所有模式可在既定搜索结束后少返回；第三阶段 PRE/IN 仍可少返回，POST 按 exact/error 策略。内存、基本去重、快照及资源正确性不能延期。P02、I05、O 等跨阶段用例按设计说明验其当期适用部分，第三阶段再验新增协调行为。

## 每个任务的证据

先由 `taskctl.py template TASK_ID` 生成 JSON 报告，保存到任务自己的证据目录后填写。报告是索引，原始 SQL、计划、日志、数据摘要及结果比较文件必须真实存在。

必填：task_id、设计 SHA、目标仓路径/HEAD/存储、dirty 状态日志、改动文件、实际命令/工作目录/退出码/预期退出码/日志/验证目的，以及每条 Axx 完成条件的 PASS、解释和证据文件。`blocking_issues` 必须确实为空才能完成；任务外仍存在的问题放 `remaining_out_of_scope`，不能把本任务失败移过去。命令记录不应包含密码或 token。

`expected_exit_code` 允许记录设计明确的负向测试，但必须说明预期错误及匹配依据；不能把构建或正常查询失败改填预期非零来通过。纯设计/核验任务至少记录源码检查或最小实验的真实命令；实现任务必须包含相应构建和运行验证，不能用 `echo PASS`、编译成功或包自检替代功能证据。

```bash
# 先自行运行验证并保存真实日志，再生成/填写报告。
python3 "$P/scripts/taskctl.py" template F-04 > "$P/evidence/F-04-report.json"
# 实际报告里的相对路径以报告所在目录为基准。
python3 "$P/scripts/taskctl.py" complete F-04 --actor implementer --report "$P/evidence/F-04-report.json"
python3 "$P/scripts/taskctl.py" check-evidence
python3 "$P/scripts/taskctl.py" list-ready
```

只有当前活动任务能完成，依赖未完成不能开始后续任务。工具检查报告字段、退出码、必填完成条件和证据存在性，保存文件 SHA-256；它不执行报告中的命令，也不能自动判断日志是否真的证明语义。执行者必须据原始证据评审，阶段门再核对完整性与版本。未启动的目标、未实现的 target、占位日志不能登记为通过。

证据文件不要覆盖，特别是完成后日志会被哈希校验。一次失败重试保留旧日志，新增尝试文件。状态只经 taskctl 修改；阻塞使用 `block TASK --actor ... --note ...`，解决后 `resume TASK --actor ... --note ...` 再 start。用户的红线变更确认需独立记录，complete 不是批准变更的工具。

## Oracle 对照与性能

Oracle 已有原始证据在上级主题的验证目录，索引见 [Oracle 证据入口](Oracle证据入口.md)。使用与基线一致的数据、查询向量、距离、参数及原 SQL 比较，保留重复、NULL 和 SQL 规定的顺序。不能用 sql/ 中新造的烟测数据替代既有 Oracle 非唯一基线，也不能改 SQL 或加入 DISTINCT/tie-break 修复差异。

行为与结果分别验收；Oracle 单端成功、计划外观、同候选局部试验或 Recall 达标均不足以标记端到端兼容。未覆盖形态先补 Oracle 证据。释放本次启动的服务但不删除容器/数据。性能只用 Release/O2、同数据/质量/缓存口径，报告实际少返回、原始结果、时延、内存及临时文件，不把 Debug 数字当性能结论。
