## 构建与启停

```bash
W=/home/qiumc/data/code/cpp/openGauss-vector-filter-p12
I=/home/qiumc/data/code/cpp/.install/diskann-vector-filter-no-include-p12-release
D=/home/qiumc/data/code/cpp/.runtime/diskann-vector-filter-no-include/data

B=/home/qiumc/data/code/cpp/deliverables/hybrid_vs_milvus_bench/build_release.sh

# 首次/头文件/配置变化时 full；仅 cpp 时 incremental；仅启停时 restart。
CODE_BASE="$W" GAUSSHOME="$I" PGDATA="$D" PGHOST="$S" PGPORT=55450 JOBS=6 bash "$B" incremental
env LD_LIBRARY_PATH="$I/lib" "$I/bin/gsql" -X -h "$S" -p 55450 -d regression -c 'select version();'

# 测试结束停止本轮不再需要的实例，保留数据。
env LD_LIBRARY_PATH="$I/lib" "$I/bin/gs_ctl" stop -D "$D" -m fast -w
```

数据目录已初始化，不能覆盖正式仓 topk_test_data。`PGHOST` 也要进入服务器启动环境：当前源码的自主事务连接没有在 conninfo 中写 host；缺少它时，函数创建会连接默认 socket 而失败。初始管理员走指定 Unix socket，本基线不依赖 TCP 免密。

构建后同时核对 Git HEAD/dirty、进程 `/proc/<pid>/exe`、安装二进制与 SQL version。测试脚本/SQL/expected 的修改不改变内核 ABI，不因此重做 full；内核头文件变化仍必须 full。Debug 只用于功能/正确性，性能任务另用统一 Release/O2 脚本并核对版本。

## 已实现的真实测试 target

`openGauss-vector-filter-p12/src/test/regress/GNUmakefile` 已新增 `diskann_filter_baselinecheck`，实际调用同目录 `run_diskann_filter_tests.py`。target 不启动服务或重写 golden，必须传入全部隔离参数；输出目录必须不存在，以保留每次原始结果：

```bash
P=/home/qiumc/data/code/cpp/公共文档/openGauss类Oracle向标融合/执行包
RUN_OUTPUT="$P/evidence/remove-covering-index-20261011/填写新的运行目录"

  DISKANN_FILTER_INSTALL="$I" DISKANN_FILTER_DATA="$D" \

```

Python 依赖 `psycopg2`，本机已安装。runner 在执行 SQL 前读取真实 data_directory，核对指定数据目录及进程二进制；只允许专用 diskann-vector-filter 数据目录。原 `diskann_vector.sql` 会创建/删除临时 test 库并返回 regression，故不能向业务实例运行。

runner 复制本次 SQL/expected 和原生比较器到独立输入目录，使用真实 `pg_regress`，明确传入 `-c 0 -d 1 -p 55450`，不让驱动转换全量模板或改源码树的预期文件。`--port` 本身不能代替其每条 gsql 实际使用的短参数 `-p`。

## 数据与检查范围

- 七项独立回归继续运行，旧覆盖索引专属 EXPLAIN 标签需按真实差异移除，业务预期不能放宽：DiskANN DDL/DML、UNION 列投影、安全矩阵、ANN 距离复用及生命周期。
- 新 `diskann_filter_baseline.sql` 在专用 schema 创建 64 行 AStore documents、普通 L2 DiskANN、标量 B-tree 和含重复 bucket_id 的业务表。九条布尔断言检查存储、标量/Join 结果多重集、业务重复、更新回滚及维护；参数化执行的已知最近 ID 为 7、51、7。结束时删除自身 schema，临时表随会话结束。
- runner 在原生回归通过后执行实际取消：观察自身 pg_sleep 语句进入 active 状态，再发出 cancel，要求 SQLSTATE=57014，之后 SELECT 1 成功。这是普通执行器前置检查，搜索内 PRE/IN/POST 的取消仍须后续任务专门验证。
- 新 fixture 的首份 expected 从实际输出建立前，检查了九个 true、已知参数结果与真实 Ann Index Scan。已有 SQL/主 expected 未改写。旧 `ann_orderby_distance_reuse` 两个距离相等的行允许交换顺序，使用原生 `_1.out` alternative；其余字符和结果完全相同，证明见 E-02 的 native-tie-proof.log。这不改变查询、K、返回 ID、多重集或 Oracle 兼容规则。

`summary.json` 保存版本/进程、实际原生命令、退出码及取消证据；`run/results/` 为原始结果，`run/regression.diffs` 保存失败差异。整套成功才退出 0，失败不覆盖 expected，也不自动回退或换查询。失败日志与已解释问题继续保留在各任务 evidence 中。

## 无覆盖索引版本的完整功能复验

当前新安装、数据和 socket 为上述 `no-include` 路径。2026-10-11 新 catalog 的普通基础19项、原生8项和前两阶段1439项功能复验均通过；这不等于质量、时序、性能或完整阶段门重新通过。详见[新基线验证记录](移除覆盖索引与新基线验证记录.md)。

完整 runner 支持显式 `--source/--install/--runtime/--inputs`；输出自动转换为绝对路径。它在测试前串行创建自己的 Oracle、Join 登记和宽行成本 fixture，避免建索引长事务干扰 VACUUM/槽位复用。Oracle 原始导出仍作为不变输入，不能换成旧 openGauss 查询结果。输入冻结文件必须与当前源码和文件哈希一致，输出目录必须是全新目录。

```bash
python3 "$P/scripts/run_p12_release_checks.py" \
  --source "$W" --install "$I" \
  --runtime /home/qiumc/data/code/cpp/.runtime/diskann-vector-filter-no-include \
  --inputs "$P/evidence/remove-covering-index-20261011/frozen-source-final.json" \
  --output "$P/evidence/remove-covering-index-20261011/填写新的完整复验目录"
```

失败后可用 `--start-at <组名>` 仅继续剩余检查；结果标明 continuation 和跳过组，必须合并同源码身份下先前真实通过的记录，不能把续跑的 PASS 当作完整运行 PASS。本次失败日志不覆盖，实际合并结果见 `functional-revalidation-summary.json`。

旧特性前安装含覆盖索引，不能用于新性能对照。性能测试须先从新基线独立构建 BEFORE 安装，再重新完成等结果/召回的预热、质量和 ABBA 窗口；当前基础回归不提供性能结论。
