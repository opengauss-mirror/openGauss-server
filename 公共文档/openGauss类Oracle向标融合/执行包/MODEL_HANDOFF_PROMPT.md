# 编程模型交接入口

把以下说明连同本执行包交给后续实施者。它描述实施工作流；用户只要求审阅或生成执行包时，不因此开始开发、构建或运行 SQL。

## 启动与恢复

1. 读取工作区和目标源码中适用的 AGENTS.md，完整阅读本包 README、继续开发交接、已知未闭合事项；读取设计 §0、§1.2、§4.2、§17.4～§17.5 和 §20.4。
2. 运行 README 的 validate、只读 preflight、taskctl list-ready。存在 active_task 时执行 `show` 恢复该任务，不领取另一个任务，不重复已完成工作。
3. 初次实施从 E-01 开始。绑定目标仓、存储声明与 baseline/migration 模式；新同源仓用全新状态目录。先核实目标仓行为和真实存储，再制定迁移方案，不能把本仓源码事实当成同源仓事实。
4. 对所选任务执行 `show`，完整阅读 design_sections、steps、acceptance 和源码入口及直接依赖。source_refs 是当前基线定位，不是目标仓能力证明；迁移先建立符号映射。
5. 在本轮授权范围内开始一个依赖已满足的任务，逐步实现并验证。维护原子任务记录，必要的直接依赖变更一并说明；不要因常规文件范围调整引入额外确认流程。

## 必须保持的红线

- 三种基准计划以设计 §1.2 和本包快照为准，复用原生 AnnIndexScan/Join/Sort/Limit，不新增 VectorFilterScan/Build/Custom Scan 包装或只改 EXPLAIN 外观。
- PRE 真实资格子树完整 EOF/Seal 后再图搜索；IN 在搜索内同步执行真实 SubPlan，单表也有 Tid Scan。输出 Join 保留非唯一匹配、业务列和 NULL 语义，NL 内侧允许每次多行。
- PRE/IN 各阶段均不做精确搜索。只有第三阶段 POST 在同一计划/AnnIndexScan/AM descriptor 中切换精确入口；不得保存第二套普通 Exact 计划。
- 候选去重只限真实扫描周期；最终 K 计完整 SQL 结果，不能去业务重复、偷插内层 LIMIT 或跨 NL ReScan 复用已输出状态。所有读取保持当前语句快照。
- Oracle 行为与最终结果分别验收。有限基线不是任意输入一致的证明；不以 recall、改 SQL、改 expected 或近似算法差异免除结果红线。
- 内部排序/补批、AStore HOT/heap 接口、“无需存储修改”只属于已经核验的基线。迁移须按真实 DiskANN 与 AStore/UStore 等存储另定接入方案，不能仅替换名称。
- 确需改变用户已确定的计划/行为/结果/存储边界时，先完成可审核的冲突证据及具体替代方案，再按设计 §0.3 请求用户确认；未确认不实施越界部分。授权已覆盖的常规修正无需重复请示。

## 实施、验证与交接

- 保护既有 dirty 文件和用户数据；必要时使用隔离工作树，并明确采用的基线。不要 reset、clean 或混入无关修改。
- 使用工作区统一构建脚本：仅 cpp 优先增量，头文件变化或首次/配置变化必须 full；性能使用 Release/O2。显式传入目标源码、安装、已初始化数据目录与空闲端口，核验实际二进制/version/HEAD。
- E-02 先交付真实回归入口，不能引用尚不存在的 target。附带 SQL 仅是起点，需补齐任务规定的并发、取消、参数、资格时序、模式切换和 Oracle 对照。
- 每项保存真实命令、退出码、原始日志、SQL/数据摘要、实际计划和比较器输出。用 taskctl template 生成报告，逐条填写后 complete；占位模板、未测/取消/失败不得写 PASS。
- F-00 等任务细化设计后，按 README 先评审影响，再用 sync-design 同步并重开受影响任务；保留原凭据。该命令不能批准红线变更，任务/验收/计划变化须单独维护执行包。
- 遇到具体阻塞时用 block 记录证据和原因；不要篡改验收条件。能独立继续的已授权任务可继续；恢复 blocked 前说明如何解决。F-00/F-09 未完成不阻塞前两阶段，PRE 空域和基础成本问题不能推到第三阶段。
- 完成后检查证据，再列出 ready 任务，在用户授权的实施范围内继续。结束时更新交接记录，报告完成项、实际验证、未解决事项和下一任务，并恢复本轮不再需要的服务。

任务工具只检查依赖、格式和文件完整性，不能替你判断设计正确性、代码质量、用户授权或 Oracle 一致性。
