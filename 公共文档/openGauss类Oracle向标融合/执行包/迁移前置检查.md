# 同源仓迁移前置检查

权威约束为设计 §0.5。先确认事实，再制定方案，然后实施；迁移到同样叫 AStore/DiskANN 的仓库也要重新检查。目标存储为 UStore 时，不预判必然需要存储重构，也不复用 AStore 不改存储的结论。

## 基线记录

填写目标仓路径、分支/HEAD、dirty、构建配置、运行二进制和 version、目标表真实存储、索引定义/配置、数据目录/端口、测试数据摘要和服务初始状态。源码存在某函数只能提供定位，必须沿调用链确认并保存必要的最小实测。

| 主题 | 要核实的实际行为 | 必备证据 |
|---|---|---|
| 排序 | AM/Executor 哪层排序；单批/跨批；原始距离或内部距离；上层 Sort 是否仍真实执行 | 源码符号、调用/计划与输出顺序 |
| 补批和结束 | 是否有补批、谁触发、按什么数停止、K 是否内截断、批结束是否等于 EOF | 候选/调用/结束时序，稀疏过滤与不足 K 用例 |
| 过滤与重扫 | qual 位置、runtime key、Limit 接线、真实 ReScan 与局部 Probe | 参数变化与资源释放记录 |
| 表存储 | 实际 AStore/UStore 等类型，TableAM 和 DiskANN 基础读写是否可用 | 实际 DDL/catalog/计划/普通 DML 回归 |
| 行身份 | 索引成员标识如何找到同快照可见版本，更新/删除/复用如何判别 | 源码与并发旧新快照实验 |
| PRE/IN | 集合身份如何对齐成员；Tid Scan 输入语义、key 核验、锁与 pin | 逐候选/完整源测试，不能仅照搬 HOT/heap API |
| 第三阶段 | 完整索引域、并发页边界、反馈作用域是否适用目标仓 | 目标仓独立的 F-00/F-09 证明和验收 |

## 方案必须回答

1. 哪些原实现可复用，哪些需适配，哪些基础能力缺失；每个结论关联已确认的事实，未知项保持未知。
2. 改动落在哪些现有 Planner/Executor/AM/存储接口；不会为套用本仓代码而先搬入整套旧内部排序/补批。
3. PRE 集合、IN 可见版本定位、候选去重、同快照读取和 POST 精确域如何在目标存储中保持合同。
4. 所需基础修复与本特性改动如何区分，三阶段依赖和针对目标仓的验证方法是什么。
5. 若现有红线确实无法保持，给出失败证据、具体替代计划和影响，按设计 §0.3 取得用户对该变更的确认后再实施。

E-01 在 migration 模式下的报告须提供 `scan_behavior_evidence`、`storage_evidence`、`migration_plan` 三个真实文件。填写文件路径不等于获得变更批准；相应用户决定应另附原始依据。M01/M02 的实施后验证留在目标仓各阶段，不能在 E-01 的前置调查时提前宣布全程通过。
