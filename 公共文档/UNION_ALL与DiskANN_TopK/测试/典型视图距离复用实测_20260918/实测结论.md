# 典型 UNION ALL 视图距离复用实测

## 1. 结论与边界

2026-09-18 已在现有实例实际执行：`WHERE + 单个距离 ORDER BY + LIMIT 10` 支持在 delta 的 DiskANN 分支生成并执行距离引用；snapshot 的普通扫描/反连接分支仍执行 SQL 距离表达式，delete 分支只提供 row_id。

不能把这个结论扩大成“此模板的所有变体都会复用”：

| 场景 | 本次实际计划 | AM 距离复用 |
|---|---|---|
| WHERE | Append；仅输出 row_id | 没有排序距离，无须复用 |
| WHERE + LIMIT 10 | 顶层一个 Limit + Append | 没有排序距离，无须复用 |
| WHERE + 距离 ORDER BY，无 LIMIT | Sort + Append；delta Seq Scan | 本次不复用 |
| WHERE + 单个距离 ORDER BY + LIMIT 10，诊断选路 | Merge Append；delta Ann Index Scan；snapshot Merge Anti Join | delta 生成距离引用，支持 |
| WHERE + 距离 ORDER BY、row_id + LIMIT 10 | 两分支 Sort；delta Seq Scan | 本次不复用 |
| 与单距离 Top-10 相同，但保留默认顺序扫描设置 | delta Seq Scan + Sort；snapshot Hash Anti Join + Sort | 小数据量自然计划未选择 DiskANN |

`enable_seqscan=off` 只是提高顺序扫描成本，不是禁止所有 Seq Scan；不匹配索引路径的查询仍可能顺序扫描。这里同时设置 `enable_bitmapscan=off`，仅用于会话内诊断选路，不是生产建议。

## 3. 实测 SQL 与开关

```sql
SET enable_union_all_required_columns_pushdown = on;
SET enable_union_all_diskann_topk_pushdown = on;
SET ann_orderby_distance_reuse = l2;

-- 只为在已有小数据上观察 DiskANN 路径：
SET enable_seqscan = off;
SET enable_bitmapscan = off;
SET enable_indexscan = on;

EXPLAIN (ANALYZE, VERBOSE ON, COSTS OFF, TIMING OFF)
SELECT row_id
FROM union_all_topk_onecol_test.gs_1w_1bucket
WHERE title IS NOT NULL
ORDER BY embedding <-> '[0.1,0.2,0.3,12.8]'::vector ASC
LIMIT 10;
```

自然选路测试先于诊断开关执行，完整输出中第一个 EXPLAIN 即自然计划。不能把使用了诊断开关的 DiskANN 计划描述为默认成本选择。

               ->  Limit (actual rows=6 loops=1)

                     ->  Ann Index Scan using delta_embedding_diskann on union_all_topk_onecol_test.delta_t (actual rows=6 loops=1)

delta 的 Ann Index Scan 本身输出双括号距离引用；snapshot 的 Merge Anti Join 输出普通单括号 SQL 距离表达式。title 仍用于 Filter，但未被加入向上输出的 targetlist；snapshot 的 embedding 只在分支内供距离计算。

上层节点的双括号还可能只是原有槽位 Var 的反解析，不等同于 AM 复用证据。此处关注的是 **Ann Index Scan 自己的 targetlist**，并结合下方开关对照与代码准入路径。

## 6. 实际查询结果与核验

开启距离复用、只关闭距离复用、完全禁用索引路径的普通 Seq Scan 参照，均实际返回以下 10 个 row_id，顺序一致：

```text
 row_id
--------
    101
    102
      5
      6
    103
    107
      4
      7
    108
    104
(10 rows)
```

最终脚本共执行 **12 个 EXPLAIN ANALYZE 和 12 个原始 SELECT**。自动核验结果：

- 五种 SQL 变体逐一对照 `l2/off`，本次返回序列全部一致。
- 单距离 Top-10 的开启、关闭、自然计划与全顺序扫描参照，返回 ID 及顺序全部一致。
- 只有 WHERE 与 WHERE + ORDER BY（无 LIMIT）均返回 37 行；WHERE + LIMIT 返回 10 行。
- 开启/关闭复用的目标计划都包含一个 delta Ann Index Scan；只有开启时该扫描 targetlist 显示距离引用。
- 单距离 Top-10 保留全局 Limit，并分别存在两个分支 Limit。
- 没有 ORDER BY 时 SQL 不承诺顺序；本次观测到序列相同不能扩大为有序性契约。
- 本轮是功能/计划/结果验证，没有增加函数调用计数器，不把双括号或一次 EXPLAIN 成功等同于独立证明“运行期原距离函数调用绝对为 0”。
- 本次与全扫描结果一致只适用于该小数据集，不代表 ANN 在其他数据集上必然达到全量精确 Top-K。
- 日志计时不是性能对比：Debug 构建、单次执行、缓存状态未控制，不能据此比较开关性能。

## 7. 两个可选语法的当前边界

### 7.1 只有 ORDER BY，没有 LIMIT

本次实际生成 `Sort → Result → Append`，delta 使用 Seq Scan 计算距离，未出现 Ann Index Scan。

当前 `diskann_topk_outer_query_is_safe()` 同时要求非空 `sortClause` 和合法 `limitCount`。列裁剪的 order-key projection 可以让分支只传递标量距离，但它不等于建立了 AM 有序扫描；“标量已经在下层算好”与“标量来自 AM”必须区分。

### 7.2 ORDER BY 距离后追加 row_id

本次实际生成 delta 的 `Sort → Seq Scan`，即使已关闭 enable_seqscan，也没有选择 DiskANN。

当前 `match_pathkeys_to_index()` 要求请求的排序键全部匹配索引排序能力；无法匹配 row_id 时放弃该排序匹配，不把“仅匹配向量距离前缀”当作完整路径。此外距离复用改写本身要求 `indexorderbyorig` 恰有一个表达式。因此不能将模板中的任意 `[, ...]` 都列为当前已支持的距离复用路径。

这些解释对应[preptopk.cpp](../../../../src/gausskernel/optimizer/prep/preptopk.cpp)、[indxpath.cpp](../../../../src/gausskernel/optimizer/path/indxpath.cpp) 和 [planner.cpp](../../../../src/gausskernel/optimizer/plan/planner.cpp)；运行期准入还受 Heap、非 bucket、非 PQ 等检查约束。WHERE 本轮具体为 title IS NOT NULL，没有穷举任意复杂过滤表达式。
