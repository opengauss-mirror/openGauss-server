## 2. 修复方式与改动范围

在 `ann_orderby_join_expr_consumes_distance()` 中，对 Var/Param 先调用 `getBaseType()` 解包 domain，再判断：

```cpp
typeId == FLOAT8OID || type_is_rowtype(typeId)
```

匿名 RECORD、命名复合类型及其 domain 可能封装了距离，未知字段依赖按不安全处理。统一 helper 继续覆盖 Join 条件、Join 后过滤、Merge/Hash 条件及 `nestParams`。没有修改 DiskANN AM、执行器或距离转换公式，也没有禁止按整数 id 连接的透明 Join。

压缩包根目录为 `ANN距离复用_Join透明透传迁移包/`。

- `patch/ANN距离复用_Join透明透传.patch`：相对于源仓 `3dbecdd31268` 的该小功能完整补丁，包含 P1。
- `patch/ANN距离复用_Join透明透传_P1增量修复.patch`：相对上一版 Join 迁移包，仅补 P1，适合已经迁移旧版 Join 功能的仓库。
- 两份补丁二选一，不要连续叠加。大差异同源仓应根据设计/迁移文档按职责移植。
- `openGauss-server/` 下仅包含指定三个文件，按原始层次保留。
- `docs/` 包含更新后的详细设计、迁移指南、本文和原生回归日志。
- `SHA256SUMS` 为包内文件校验清单。

主补丁及增量补丁均需通过 `git apply --check`，实际应用到各自基线后，三个结果文件应与包内副本逐字节一致。本次已完成该校验。

回归期望输出保留 gsql 表头/列对齐所需的尾部空格，Git 可能提示 trailing whitespace；不要使用 `--whitespace=fix` 修改 golden。内核代码本身通过空白检查。

### 5.1 不可遗漏的前置修复

本包仍不包含旧的 `union_all_replace_source_chain()` 共享 targetlist core 修复。源仓实际编译测试的工作树已有该独立修复；本次导出只保留 Join 相关差异，不把其他本地变化混入包内。

因此，包内 `planner.cpp` 是基线加此功能的比对快照，不应整文件覆盖目标仓，更不能用它回退目标已有的共享 targetlist 保护。目标开启列裁剪并执行无主键矩阵前，必须具备那项修复或等价保护。详细检查见迁移指南的前置条件。

### 5.2 已加入迁移包的前置修复复现用例

针对这个前置条件，本次在包内新增 `docs/共享targetlist前置修复复现/`：

- `01_无主键完整复现.sql` 是可直接执行的小数据用例。它不建主键、不建向量索引，强制 `Merge Anti Join -> Sort -> Seq Scan`，在 B 阶段打开 `enable_union_all_required_columns_pushdown`，正好触发旧实现的共享 targetlist 路径。
- `02_当前已修复实例实测.out` 是当前版本实际输出；B 阶段和全部三 GUC 阶段均无 core，返回 `101、102、3、3`，最后事务回滚。
- `README.md` 明确说明旧版本可能 backend core、不能在生产实例执行，并给出准确的修复步骤。

该复现用例看护的是列裁剪源头改写，不是本次 P1。迁移目标仓时，应先用它确认已有等价修复，再应用 Join 透传补丁；否则遇到无主键矩阵崩溃时，根因应归到共享 targetlist，而不是误归因于 ANN Join 透传。

修复算法必须保持以下顺序：先验证 source chain 的所有层；保存匹配 `TargetEntry*` 并按指针去重；所有验证成功后，才对唯一 entry 统一 `copyObject(candidate->expr)`。不能在遍历第一层时立即修改，也不能第二遍重新按原始 Var 查找。因为 Sort/Scan 可能共享同一份 targetlist，前一种做法会使后续查找返回 NULL 并在旧实现中触发解引用 core。
