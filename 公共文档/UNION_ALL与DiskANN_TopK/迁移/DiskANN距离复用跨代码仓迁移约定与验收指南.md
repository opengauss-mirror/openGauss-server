# DiskANN → KGN 距离复用：跨代码仓迁移约定与验收指南

## 1. 这份约定要解决什么问题

适用场景：以源端 DiskANN 距离结果复用实现为参考，在同源但代码差异较大的目标仓中适配 **KGN**。目标仓的 Cosine 距离操作符是 **`<+>`**，L2／欧式距离操作符是 **`<->`**。**用户已明确 KGN 的 L2 也不是精确距离，目标 L2 和 Cosine 都按近似距离复用约定迁移。**目标已经迁移过部分实现时，按本文审查、补齐及验证。

迁移对象是“AM 距离发布 → 执行器绑定与引用 → 上层安全消费”的能力。DiskANN 的函数名、OID、页结构、合并桶、距离公式和具体修复方式需要分别映射到 KGN，不能直接作为目标实现的事实。

本指南的缺陷统计和迁移要求聚焦距离复用，以及影响其正确性的行身份、有序性和可见性问题。`delta/snapshot/delete` 联合查询作为距离复用的集成测试场景，用于验证多分支距离传递、排序和最终 Top-K。

迁移质量应由三件事共同证明：**语义契约保留、目标调用链真正接通、针对性测试实际通过**。文件数量相同、patch 无冲突、编译成功或者查询结果正确，都只能证明其中一部分。例如，完全没有命中复用的实现也可能通过结果比较。

本约定把“保持功能”落实为可检查的代码位置和运行证据。它提供基本质量的验收标准；长期并发和性能需要另外给出对应证据。

### 1.3 已明确的目标约定与待核实事实

| 项目 | 源端 DiskANN | 目标端 KGN |
|---|---|---|
| 向量索引 AM | DiskANN | KGN；实际注册方式及 AM 标识由目标代码确认 |
| L2 距离操作符 | `<->` | **`<->`** |
| Cosine 距离操作符 | `<=>` | **`<+>`** |
| L2 复用质量 | 合格路径标为 exact L2 | **近似 L2，已由用户明确** |
| Cosine 复用质量 | 近似 Cosine | 按近似 Cosine 契约适配 |
| L2 距离转换 | 源端对合格平方距离开方 | **KGN 已有明确公式，直接遵守目标公式，结果为近似 L2** |
| Cosine 距离转换 | 源端转换归一化负内积分数 | **KGN 已有明确公式，直接遵守目标公式，结果为近似 Cosine** |
| 距离的行身份依据 | TID/owner、扫描状态及可见向量校验等 | 按 KGN 候选与可见行关联机制证明 |

用户已明确目标 AM、两种操作符、L2 的近似属性，以及两类距离都有现成转换公式。**距离转换以 KGN 既有公式为准，迁移不重新设计公式或改变其精度。**需要核对的是目标函数位置、输入参数、转换是否已经完成，以及正确接入发布通道。尚未提供目标仓源码路径，本文未宣称已读取具体公式实现。源文档中“仅允许 DiskANN”“L2 必须 exact”及源转换代码分别按本文的 KGN 范围、近似质量和目标公式适配。

此前用户还说明 KGN 索引内部不存储原始向量，并希望避免为距离复用额外回表。迁移时以此作为约束核查，分别记录：

1. KGN 现有公式在哪个入口调用，候选中保存的是转换前分数还是已经转换好的最终距离。
2. 索引是否有足够的行版本身份信息，在不读取原始向量的情况下绑定当前行。
3. SQL 的 `<->`／`<+>` 对哪种向量表示计算，与 AM 是否相同。
4. “不额外为距离回表”与“整条查询不回表”分别如何实现；读取 `row_id/title` 或进行可见性检查仍可能需要访问表。

**目标接受两类近似距离，并已经提供转换公式，这些均为迁移前提。**迁移要按目标公式正确产生和传递现有近似值，同时保证行身份、有序性和消费者边界。不要求补偿近似误差，也不要求为满足源端 exact 标记而额外回表精算。

“L2 近似”本身不说明独立 SQL `<->` 是否采用同一量化表示。迁移时仍要查清 AM、原始 SQL 表达式及原始向量参考值之间的关系；不能假定它们一定相同或一定不同。

## 4. 必须保持的语义契约

### C01：范围、开关与既有能力

1. 保持四档名称和默认 `off`，目标语义按下表定义；规划、执行、缓存和 AM 对模式的理解一致。
2. 以实际 **KGN AM** 身份限定目标准入；即使共用 `Ann Index Scan`，也不能让 HNSW、DiskANN 或其他 AM 被误认成 KGN。
3. 目标准入条件依 KGN 能力制定并映射源安全条件。源端不支持 PQ 不等于 KGN 必须不存在量化；关键是能否证明目标距离质量和消费者安全，不能直接去掉来源检查。
4. 目标存在的普通本地 heap 及其他约定正向场景必须命中。未知的 index-only、Ustore、bucket、分区、并行或远程路径在证明前保守拒绝，并记录覆盖差异；不能以 AM 名称差异为由禁用所有 KGN 复用。
5. 不隐式开启 UNION ALL 下推、列裁剪等其他开关。若目标缺少联合场景的前置能力，应明确说明对验收的影响。

| 目标 GUC 值 | KGN 允许复用的距离 | 仍需满足的条件 |
|---|---|---|
| `off` | 不使用本特性的 AM 距离引用 | 保留目标原有 SQL 表达式及独立生效的正确性保障；不代表原 SQL 一定精确 |
| `l2` | `<->` 对应的近似 L2 | 来源、行身份、消费者及有序性检查通过 |
| `cosine` | `<+>` 对应的近似 Cosine | 同上 |
| `all` | 上述两类近似距离 | 分别识别度量和质量，不绕过安全条件 |

源端 `l2` 只允许 exact L2；目标已按用户说明改为近似 L2。该差异要写进目标 GUC 说明、质量枚举和测试，不能仅改变参数取值判断。

**特别注意 INCLUDE：**源码包完整 `diskann.cpp` 中包含源基线已有的 INCLUDE 能力，源工作区后来未提交的 `amcaninclude=false` 没有导出。这两点都不定义 KGN 的 INCLUDE 能力；目标保持自身已有设置，不能因复制源完整文件而引入另一种 AM 的 DDL 或访问路径。

### C02：距离转换严格遵守 KGN 的既有公式

目标算子映射固定为 **L2 `<->`、Cosine `<+>`**。KGN 现有转换公式和实现是本节的依据；其输出已经约定为对应度量的近似距离。迁移任务负责接通与复用该结果，保留目标既有计算精度、参数、边界处理和异常规则。

| 候选值所在阶段 | 迁移动作 | 验收要点 |
|---|---|---|
| 尚未按目标公式转换的分数 | 使用对应的 KGN 既有转换入口及完整参数，保存转换结果 | 使用正确的 L2/Cosine 公式，当前 query/candidate 对应正确 |
| AM 已保存按目标公式转换的最终距离 | 直接向通道发布该值 | 不重复开方、不重复加减常数、不再次校正 |
| 执行器读取 AM 的最终值 | 绑定当前行后直接引用 | 无第二次距离转换，同一行多次引用使用同一结果 |

转换只在负责 `raw → 最终距离` 的约定环节执行一次；KGN 若已有该环节就直接复用。公式内部有哪些步骤由目标定义，不能额外套用源 DiskANN 的 `sqrt`、`1+raw` 或 `[0,2]` 截断，也不为消除近似误差补做精算。

检查所有排序消费者拿到的都是 KGN 公式的最终输出，而不是某处分支遗漏转换后的内部 raw。KGN 与 snapshot SeqScan 混合时仍核对最终值的度量和尺度一致，并按各自最终值验证合并顺序；无需为此重新推导 KGN 公式。

**KGN L2 必须标为近似 L2。**不要复用源端 `ANN_ORDERBY_DISTANCE_EXACT_L2` 来通过既有检查；可新增类似 `APPROX_L2` 的质量类别，具体名字按目标规范确定。度量种类（L2/Cosine）与距离质量（精确/近似）分别表达，`l2` 这个选项名不能作为“值精确”的证据。

新增近似 L2 后必须逐项审查：规划期准入、引用节点质量字段、copy/equal/out/read、GUC 模式匹配、执行期重核验、AM 发布、消费者保护、失效处理、预编译计划与游标。只增加枚举而漏改其他判断，会导致始终不命中、走错回退或错误放行语义消费者。

若 SQL 和 AM 都使用量化后向量，也需要证明它们用的是同一量化／重构表示、同一查询向量处理和计算口径。此时可以相对目标 SQL 验证一致性，但不能据此声称与原始未量化向量的距离精确相同。

目标两类近似值都允许用于通过保护检查的排序与最终显示。不得利用本次迁移重新定义普通 SQL `<->`／`<+>` 在 WHERE、Join 等位置的既有语义，也不能将“已接受近似距离”解释为允许错误行、过期值或量纲不一致。

保持 KGN 现有的搜索分数与转换结果使用约定；接入发布通道不能覆盖其他搜索阶段仍需使用的 raw。同一候选的转换结果可以复用，参数或候选改变后按目标生命周期失效。

保留空值、非法数值及质量标记的处理。不能把异常值改成 0、扩大误差阈值或者统一改成精确重算来掩盖接错距离来源的问题。

### C03：优化器按语义阶段迁移

源入口是 `rewrite_ann_orderby_distance_refs`。最终物理路径和 setrefs 处理完成后，才有依据判断实际 AM，以及目标表达式由哪个扫描产生。

必须说明目标仓的对应阶段，检查主计划、SubPlan/InitPlan 遍历和之后的计划处理。不能按源行号插入，也不能误放到 UNION ALL 子查询拉平前的改写入口。

只替换扫描 targetlist 中与本扫描 ORDER BY 原表达式完整匹配的项，保留原表达式用于反解析和规定的回退。索引列、查询向量、类型、算子、opclass 支持函数均要对应；不能仅按表达式打印文本匹配。

在 KGN 中分别解析 `<->` 和 `<+>` 的真实算子与函数身份，处理 schema、参数类型及重载。源端的 `<=>`、`DISKANN_AM_OID` 和距离函数 OID 都只能作为源代码线索。规划期准入、执行期重核验和 AM 发布三处必须使用一致的目标映射。

### C04：近似 L2 与近似 Cosine 都必须检查消费者

检查从产生距离的扫描到上层使用方的整条路径：

- 透传投影、排序等允许路径需符合当前设计。
- WHERE、Join、聚合、GROUP BY、DISTINCT、比较表达式、Result 条件及 InitPlan/PARAM_EXEC 等可能改变 SQL 判断结果的使用必须受保护。
- 不能只列举 Join/Agg 节点而遗漏普通 `SubqueryScan.qual`、`Result` 或参数通路。
- 递归退出一个 UNION ALL 分支后恢复上下文；不能将 snapshot Anti Join 的判定污染到独立 delta 分支，也不能反向丢失真实的不安全父节点。
- 目标新增计划节点默认需要审查；只有证明透传语义后才准入。

例：源用例中精确 Cosine 与近似值分别在 `0.00008161` 两侧，直接让近似值参与 `< 0.00008161` 会把 0 行改成 1 行。KGN 要分别为 `<->` 和 `<+>` 比较原 SQL 表达式值与 AM 近似值，选择确实位于两者之间的阈值；源数值仅说明方法。若某个夹具两值恰好相同，另选有差异的夹具或通过计划和运行路径证明保护生效。

**目标 L2 已允许近似，因此消费者保护必须同时覆盖 `<->` 和 `<+>`。**源代码中仅在 Cosine 分支检查 `approximatePlanSafe`、而让 L2 按 exact 条件直接通过的写法需要适配；近似 L2 不能继承源端 exact L2 的语义特权。

普通 `WHERE title IS NOT NULL` 不消费距离，可以正常保留。扫描本身含独立的 `embedding <-> q < threshold` 条件时，条件按原 SQL 表达式计算；不得把它替换为近似投影缓存。若外层 WHERE、Join 等直接引用被改写的距离列，则应在规划期禁止这条近似复用路径。`l2/all` 是复用许可，不取消这些边界。

### C05：引用节点的所有框架入口都要接通

`AnnOrderByRef` 至少逐项检查：

1. NodeTag/结构定义、字段初始化、类型及 collation 信息。
2. copy、equal、文本输出与读取、walker/mutator。
3. 反解析及 EXPLAIN。
4. 递归表达式引擎与融合表达式引擎。
5. 计划复制、缓存、版本门和可能的跨进程传递。

不能直接搬 NodeTag、OID 或表达式 opcode 的数字。目标已有编号、分发方式和版本协议必须一致。目标存在第三套执行引擎时，必须落实支持或明确阻止其接收新节点。

节点往返处理不能丢失排序位置、距离质量和原表达式。普通 SQL 正常不代表复制/缓存/另一引擎可用。

### C06：距离必须属于当前扫描、当前可见行

KGN 必须建立查询向量、扫描代际、当前候选与当前可见行版本的关联。源端使用 epoch、row token、TID/HOT、候选 owner 和向量校验；KGN 可使用经证明等价的 ID／版本／代际协议。**物理 TID 相等不代表相同版本的行**：删除、VACUUM、INSERT 后，同一 `(block, offset)` 可能属于新向量。

结果通道只在证明候选对应本次可见行后绑定。若走 heap 路径，在可见性处理之后绑定；KGN 自身提供可见性时说明等价的绑定点。逐行失效、被 WHERE 拒绝的行、重扫、空结果、结束和异常路径都不能把旧值带到下一行。

按距离质量和已选择的策略区分以下情况：

- 扫描开始时不允许复用：整次执行采用目标原表达式策略。原表达式本身是否精确按目标实现说明。
- 已选择近似 L2 或近似 Cosine 后出现行身份失配：拒绝发布并按契约报错；不能拿另一行的分数，也不能逐行转为回表精算以掩盖问题。
- AM 发布值无效、过期或质量不匹配：两种度量都执行相同的严格有效性检查。源端的 REINDEX 提示需按 KGN 真实原因适配。

源端 `heap_recheck` 为 exact L2 提供逐行精算回退，KGN 近似 L2 不再满足其前提。目标不能把近似 L2 接到该分支，也不能为了保留该分支引入额外原始向量读取。无回表情况下的当前行身份必须由 KGN 自身协议证明。

源端正常 L2 仍可能读取堆向量做身份校验。KGN 不保存原始向量时，不能照搬 `diskann_orderby_vector_matches` 而声称满足无额外回表要求。目标报告必须分别列出距离算术、原始向量读取、普通列访问和可见性检查的实际行为。

### C07：已收集候选按最终使用的距离有序

逐行距离正确还不够。旧合并节点曾返回 `1、0、2、1`，上层 LIMIT 或 Merge Append 会相信输入已经有序，进而错误截断或合并。

必须证明 KGN 按实际发布给上层的距离有序。若其现有机制已经能保证全局单调输出，并且距离转换、逐行校正和扩批不会破坏这一保证，可复用现有机制，并提供代码与测试证据。

若不存在该保证，采用源端对应的保护方式：完成需要的候选批次收集，对可见且符合 WHERE 的行使用最终距离统一排序，第一行发出之后不再扩批。最后一个批次不能因为已累计 K 行就从中间截断。不能机械新增物化成本，也不能在缺乏证明时跳过有序性保护。

这里的完整是指**所选候选批次完整处理**，不是遍历全表所有向量。候选的单调输出也不证明全表精确 Top-K 召回。

距离缓存、去重与排序需审查 KGN 是否存在一候选关联多行、同一行从多路径返回、过滤不足而扩批等情况；不能假定存在 DiskANN 的合并桶。需要新增排序时按 `work_mem` 管理并能溢盘，不能变成无上限内存容器。

### C08：物化排序保留执行器原有语义

- WHERE 对同一候选按原契约求值一次，不能在收集和发出两阶段各算一次。
- 用户投影延迟到真正发出的行；含 `nextval` 等易变表达式时不能对全部候选提前执行。
- target SRF 可能返回零行或多行，不能直接把基本行数当作最终输出行数。
- 检查 LIMIT/OFFSET 的边界传播和提前停止；不能截断后再补排序。
- 复制、保存和恢复 tuple 时保留 `ctid`、`tableoid` 等系统属性及对应生命周期。
- 检查溢盘、游标、rescan、提前结束及错误清理，避免旧 tuple/距离串入新扫描或资源不释放。

### C09：把源端缺陷映射到 KGN 的 MVCC、回收和去重协议

1. generic WAL 是重做记录，不提供 SQL 事务的逻辑撤销。KGN 的删除协议必须保证回滚与旧快照仍能找到可见行；不能仅凭已写 WAL 就认为事务语义完整。
2. 源端采用 VACUUM 延迟物理清理。KGN 若已有 tombstone、版本化候选或其他事务安全回收协议，可复用并证明等价；不要求所有 KGN 格式都机械套用源端的 delayed-delete 函数。
3. KGN 的稳定 ID／版本／TID 复用必须使旧距离关联失效。若使用 bulk-delete 回调，按目标真实签名、分区/bucket 参数适配；不能强转函数指针。源四参数签名不是目标既定事实。
4. 按 KGN 实际布局解释图节点、编码页或分段等存储结构。不能移植 DiskANN 的 frozen 节点、PQ 页范围或扫描起点；目标不存在的机制要明确标记。
5. 检查 KGN 的重复向量、候选合并和多路径去重。若仅因量化编码相同就共享分数，不能把它当作原始向量相同或 exact 距离的证明。容量及溢出测试使用 KGN 的真实边界。
6. 核对 KGN 的锁、pin、内存和日志生命周期。如果沿用 GenericXLog，则保留完成／中止及无修改退出语义；使用其他日志机制时审查其等价要求。
7. DDL 判断“有 INCLUDE 列”和“需要延迟删除”分别表达；只在 KGN 存在相应能力和判断时适配，不引入源 DiskANN 的 DDL 限制。

源实现不改变页格式。KGN 应尽量复用现有格式和协议；增加格式版本、强制重建索引或改变删除协议属于实质差异，必须单独说明影响。源端存在的具体缺陷不代表 KGN 一定也存在；共同的正确性要求必须验证。

### C10：GUC、缓存计划与游标保持一致策略

- 缓存计划跨 GUC 变化时，执行入口重新核验实际索引和当前模式。
- 新一次执行可以选择整次回退；已经开始的游标扫描不能因 FETCH 之间切换 GUC 而让后续行换距离策略。
- rescan 使用新的 query vector、epoch 和候选状态，不能只清空一份值缓存。
- 目标 GPC、版本门和多执行域机制需要逐项映射，不能只实现普通 PREPARE 而遗漏实际启用的缓存路径。

缓存和游标的切换测试要分别覆盖 L2 与 Cosine，例如 L2 计划在 `all→off`、`l2→cosine` 时的新执行策略，以及 FETCH 间修改模式后的扫描策略。不能沿用源端“L2 永远 exact”的假设，漏测近似 L2。

### C11：EXPLAIN 是计划证据的一部分

保持当前设计：扫描 Output 中以双层括号表示内部引用，Order By 仍展示原排序表达式，不恢复早期的一组 Distance 诊断字段。

KGN 的 Cosine 原表达式显示 `embedding <+> query_vector`，L2 显示 `embedding <-> query_vector`。扫描节点名称、索引名及类型反解析采用目标真实实现，不伪造 DiskANN 计划，也不保留源 `<=>` 作为目标 Cosine 表示。

上层 Limit 原本也可能因为 Var 展开显示双括号，因此只看到双括号不能证明 AM 复用发生。要检查对应的扫描输出、内部表达式节点，并用运行证据确认取值来源。

### C12：既有正确性修复不受 off 开关撤销

源交付包含距离复用及其审查中修复的底层有序性、删除可见性等问题。KGN 经审查若存在同类问题，应实现其对应修复，且不能因 `off` 撤销正确性保障。若目标已有完整保障，保留并给出证据；不需要仅为复制源修复而额外改动 KGN。

| T20 | 目标特有计划节点、缓存、执行路径及失效通道 | 支持路径正常，未支持路径正确拒绝；无效/过期发布按契约处理 | C01/C05/C06/C10 |

T20 的通道异常可通过可重复的测试钩子或调试注入验证，明确保存方法；临时钩子不进入交付内核。若只完成代码审查，不能写为“运行时故障验证通过”。

### 5.3 防止测试形状改变而测不到缺陷

近似准入取决于整条消费链。不能随意把目标查询改为 `CREATE TABLE AS SELECT ...`、`INSERT ... SELECT ...` 或外包聚合后再测；这可能直接让优化器拒绝复用。

沿用源回归中独立动态 SELECT 的捕获方式，在保持原查询形状的前提下保存结果。记录实际输出序号，再检查相邻距离；先对结果按 id 或 distance 重排会掩盖原输出乱序。

数值验收分为两层，两种距离都适用：

1. **复用实现正确性（主要验收依据）**：以同一 query vector、同一候选/可见行及目标已有公式为依据，核对 AM 最终值、发布、扫描绑定和最终投影。AM 若已转换就直接捕获其转换结果，不把它再次代入公式。纯复制的 float8 可用 `float8send` 逐位比较；必要的类型转换按目标既有规则比较。允许距离近似，不等于允许这个传递过程出现额外错误。
2. **既有近似质量（沿用目标标准）**：复用 KGN 已有的公式/误差/召回测试。为诊断可用独立 SQL `<->`／`<+>` 或原始向量参考记录差异，不要求两种近似距离与精确值逐位相等，也不把重新证明目标公式精度作为本次迁移前提。测试参考读取原始向量不表示正式复用路径获准额外回表。

raw、已转换值及绑定身份可由测试钩子、调试器或受控日志捕获，必须区分所处阶段并记录 query、候选及行版本对应关系。不能把最终查询输出自身当作唯一参考，做自我比较。目标也不需要存在源端同名 `l2_distance()`／`cosine_distance()` 函数。

继承 KGN 已有的距离误差和召回指标，不因搬入源代码就另设一个 exact 门槛。若目标没有数值上界，记录绝对误差、非零参考距离的相对误差和 Top-K 差异，不凭一批夹具宣称全局误差有界，也不临时扩大阈值掩盖迁移问题。迁移本身应保持同一候选的既有 KGN 分数语义，分数精度由 KGN 算法负责。

KGN 的量化策略可能使源端误差夹具不再触发，应重新构造并保存目标夹具及实际 raw/转换/SQL 值。既不能只改 `<=>` 为 `<+>` 就照抄 golden，也不能因某个夹具没有误差就宣称 KGN 始终精确。

### 5.4 Top-10 的断言要区分四件事

1. **距离值正确**：每行距离属于该行、符合当前距离契约。
2. **已返回行有序**：实际发出的距离单调，不能通过输出后重排达成。
3. **行没有错误丢失或重复**：对固定小数据检查多重集；`UNION ALL` 的重复次数也有语义。
4. **候选选择与排序比较分别进行**：先固定可复现的 KGN 候选及分数，再验证复用和联合合并；与 SeqScan/原始向量真值比较用于独立记录召回与近似质量。

KGN 的 L2 和 Cosine 都可能因近似误差改变相邻行顺序及 Top-K，即使全部行都在候选中，也不保证与原始向量精确排序的 ID 相同。因此不能沿用源 exact L2 的“off/on 与精确结果必须完全一致”断言；也不能把所有差异一概归为召回问题。

联合 Top-10 应基于各分支实际使用的最终值另算参考：KGN 分支用已核对的近似距离，SeqScan 分支用其原表达式值，再独立排序、截取及比较。允许两类分支精度不同，但尺度必须相同；这可以证明合并和截断正确，不证明精确全局 Top-10。近似顺序发生变化后，分支 LIMIT 之前也必须按相应最终距离满足有序性。

若距离并列，SQL 没有规定相同距离之间的唯一顺序。主 Top-10 对比可以构造无边界并列的夹具；并列专项检查合法集合和距离顺序。为测试随意增加 `ORDER BY distance, id` 可能改变 ANN 路径，必须重新确认命中。

### 5.5 必须证明优化真实发生

至少选择一个正常 L2、一个 Cosine、一个重复引用场景，提供以下证据：

- 最终扫描确实含内部距离引用，并实际使用 **KGN**。
- 运行时读取了本次 AM 发布值。
- 匹配的投影不再独立调用一次完整距离内核；重复引用复用行级值。
- 近似 L2 和近似 Cosine 正向场景都实际读取 AM 分数；整次原表达式策略与复用分别记录，不能以全部回退伪装成功，也不能出现沿用源 exact L2 的逐行精算回退。

可以利用已有内部计数、调试器或临时探针。应区分“AM 搜索内完整距离计算”和“投影额外计算”：前者仍然可能存在，不能要求总调用次数为零。计划双括号和结果一致性不能单独替代这组证据。

按此前无额外回表的要求，另行确认 KGN 没有为了距离转换或源式身份校验增加原始向量读取；若增加，说明具体路径和次数，不能仍宣称满足该约束。原有 WHERE、可见性或普通列取值的表访问应单独统计。

## 6. 计划变化的归因约定

记录以下三组，而不只比较迁移前后两份计划：

| 组别 | 代码 | GUC | 主要用途 |
|---|---|---|---|
| A | 目标仓迁移前 | off，或目标尚无该参数 | 记录目标原有行为 |
| B | 目标仓迁移后 | off | 验证基础正确性修复及其他迁移影响 |
| C | 目标仓迁移后 | l2/cosine/all | 验证复用是否生效、语义是否保持 |

三组都在 KGN 目标仓、使用同一组目标操作符。**A→B** 的变化可能来自目标实际需要的 MVCC/候选排序修复；若 KGN 已有等价保障，不应为模仿源实现而制造差异。**B→C** 主要用于观察复用开关的影响。不能用源 DiskANN 与目标 KGN 的计划差异直接归因于距离复用。

B→C 可能因为从原表达式取值切换为 KGN 近似分数，改变显示值、顺序和 Top-K；这不自动构成缺陷。应先核对最终投影是否等于当前候选按契约转换的 AM 值，再检查排序、合并和消费者保护。两种度量都按此标准分析，不能继续要求 L2 off/on 数值逐位相同。

对照时固定 SQL、数据、统计信息、索引、会话参数和构建类型。需要跨二进制比较时使用可重复的隔离数据集；旧索引升级测试另外保留原物理索引。

每份重要计划差异至少记录：

1. 变化发生在哪个节点、输出表达式或访问路径。
2. 是引用替换、消费者保护、子查询消除、行宽/成本变化还是候选排序造成。
3. 用什么代码路径和对照实验支持归因。
4. 对结果、顺序、过滤次数和性能有什么影响。

目标 CBO 可能选择不同的 Join、Append/Merge Append 或 Scan。允许有依据地调整 expected 的计划文本，但必须保留所需语义断言。自然计划不命中目标形态时，用目标可用的 hint/GUC 构造定向测试，并同时保留自然计划；不能通过 hint 强行声称默认计划表现相同。

### 7.3 确认用例真正覆盖了目标场景

本节讲的是“怎样证明测试进入了要检查的分支”，与上面的缺陷总数无一一对应关系。修复后应验证触发条件成立时错误不再出现，不要求修复后的系统再次产生历史错误。

#### 7.3.1 TID 回收

源证据中的等待秒数取决于源库延迟清理设置，迁移时不能机械照抄后认为已经复现。

KGN 使用 heap TID 时，必须观察 VACUUM 实际清理、插入的新行使用旧 ctid，随后检查该新行距离。若使用另一种稳定 ID／版本映射，应触发并验证它自己的复用或更新边界。未形成要测试的身份变化时，结论是“本次未触发”，继续调整夹具或同步条件。

#### 7.3.2 旧快照

先建立读者快照并查询，随后让写者删除、提交、VACUUM，再让旧读者和新读者分别查询。保存两会话输出和同步先后关系，不能仅凭同时启动两个脚本判断交错发生。

#### 7.3.3 溢盘、扩批与缓存计划

宽行和小 work_mem 只是溢盘触发条件，还需在可用的排序统计、日志或调试信息中确认外部排序实际发生。同理，扩批需确认调用了后续批次，缓存计划需确认经过目标缓存路径，而不能只依据参数设置判断覆盖。

#### 7.3.4 旧索引与历史损坏

必须在迁移前版本的 KGN 中创建旧索引，并保存版本、OID/relfilenode 或目标等价物理标识；升级后直接检查。不能先 REINDEX 再宣布兼容性通过。这里不要求 KGN 读取 DiskANN 索引格式。

源修复不承诺恢复 DiskANN 旧 immediate delete 已经破坏的图连接，这也不是 KGN 已有缺陷的证据。目标实际遇到旧索引损坏时，应记录 KGN 的现象及修复边界，与迁移后新产生的问题分开处理。

### 8.1 构建证据

先读取目标仓构建规范。本特性改变多个头文件，验收应从能保证所有依赖对象重新生成的全量构建开始，记录配置、编译器、源码提交及 dirty 差异。

核对服务实际可执行文件路径、安装目录和版本。若遵循先测试后提交，版本字符串可能仍是提交前 HEAD，应以构建日志和源码差异证明测试内容，不能只看字符串。

遇到差异应分为：迁移漏项、目标 API/语义差异、源实现缺陷、合理计划差异、测试前提未形成、环境问题。

每个问题给出触发 SQL/步骤、实际结果、预期结果、根因和修复后证据。源实现若有可复现缺陷，应按契约处理并明确记录，不能仅为保持代码相似而照搬错误；也不能把无证据的怀疑写成已确认缺陷。

## 9. 迁移完成的判定

只有同时满足以下条件，才可给出“基本迁移验收通过”：

1. 39 个源文件及依赖的处理结论齐全，没有未解释的漏项。
2. C01～C12 在目标调用链中落实；目标差异有明确说明。
3. 目标全量构建与原生三组回归通过，重要 negative/positive 场景确实命中。
4. 必测矩阵全部通过，或有可核验的不适用结论；未触发项不算完成。
   §7.2 的每项历史缺陷均应有对应处理结论，不能把四组触发条件示例当成完整缺陷覆盖清单。
5. KGN `<->` 与 `<+>` 的近似质量标记、当前候选的转换与传递、消费者保护、实际顺序、行身份及事务可见性均有证据。L2 近似已获明确约定，不能再以“不等于精确 SQL 距离”为理由判定迁移缺口；过期值、错误行和尺度混用仍属于实现错误。
